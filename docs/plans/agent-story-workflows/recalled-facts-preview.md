## Problem and bounded decision

Recall reaches a linked peer outside generation's renderer prefix, but the
existing author preview request cannot select that evidence. Add optional author
selection to an existing Needs review block's new proposal. Do not fabricate a
review cause or introduce another generation/replacement workflow.

The first slice accepts one unspecified-time recall query and up to eight
resolved baseline field identities with expected revisions. Exact displayed
endpoint-name and connecting-path receipts accompany the selection. Shared recall
is re-run inside the existing proposal capture read transaction. Only chosen
supplemental values and necessary names/untimed paths enter this preview. Existing
automatic context remains as-is; unselected evidence outside it is not supplied.

## Custody and ownership

The request owns bounded author intent; canonical recall owns value/eligibility
resolution. The current proposal binding and existing field/name/relationship
receipts own consumed evidence. Capture, recording and atomic acceptance recheck
the same expected selection; ABA/deletion/changed topology cannot pass by restoring
displayed text. Existing proposal IDs remain immutable. Acceptance records the
current selected inputs through existing generation dependencies, so subsequent
source edits produce existing Needs review.

Selection is transient per target/session/displayed packet. Resetting selection
does not touch saved screenplay, manual drafts or pending proposals. Empty facts
have the existing no-selection behavior; associated selectors are unused intent.
Entity-scoped Bible membership custody remains distinct from supplied values.
No new persistence, embedding dependency, context link or automatic retrieval.

## Temporal boundary

Both recall and preview story time must be unspecified for nonempty selections.
Snapshot-backed facts, unresolved identities and omitted values cannot be selected.
The UI explains these limits and unknown name custody explicitly. The backend
refuses forged or unavailable selectors. Timed values are not relabelled as
baseline evidence; temporal consumption requires a separately reviewed extension.

## Acceptance and qualification

1. A selected far-peer baseline reaches the actual provider prompt; its unselected
   sibling value is absent, and exact canonical source revisions are recorded.
2. Empty selection retains existing capture/context behavior.
3. Field/name/path edits, ABA, clear/deletion, snapshot reclassification, omission,
   forged receipts and bounds refuse capture, late recording and stale acceptance.
4. Preview/rejection/refused acceptance preserve exact manual screenplay, unrelated
   drafts, placement, locks and existing proposals; proposal IDs cannot be amended.
5. Explicit acceptance changes only its target, refreshes exact consumed custody,
   and a later selected fact/name/path edit derives impact. Fresh explicit
   selection can restore omitted consumed evidence for another reviewed update.
6. Native qualification should show Bible, timeline and screenplay with a checked
   fact and pending proposal, labelling synthetic provider responses. Local
   GTK/WebKit admission is checked; no ONNX403 bypass or publication to obtain
   hosted qualification is authorized for this local-only milestone.

Source, local evidence and any later native qualifier remain separate.
