# Manual fact native qualification controls

## Purpose

Qualify exact application source `1aab490a7518faf89285c72404f429e63d1e0d4e`
through ordinary native editing and explicit fact review, with labelled synthetic replies.

## Contents

| File | Responsibility |
| --- | --- |
| `ManualFactControls.svelte` | Visible QA replay, association ABA, read-only impact and labelled transport fault controls. |
| `manualFacts.svelte.ts` | Forward unchanged public commands/reads; hold one actual Save acknowledgement and fail/hold selected detail reads with explicit receipts. |

## Problem

Exact request/decision replay and consumed-association edit/restore need explicit
native fixture controls without changing production files or bypassing commands.

## Constraints

The nine-file qualifier delta is enumerated and admitted against the frozen source.
No model downloads, real inference, direct database writes, DOM/IPC injection or
automatic product actions are permitted. Detail failures and acknowledgement/read
delays are explicitly synthetic qualifier transport seams, not natural outages.

## Decision

A separate Vite config inserts the visibly labelled fixture controls into the
native test host. Wrappers forward analysis and decisions unchanged through the
existing public command API. Ordinary Save, select, Analyze, Reject and Accept
remain production controls driven with native X11 input and AT-SPI geometry.

## Alternatives Rejected

Direct SQLite writes and DOM scripting would bypass the ownership and native
behavior this qualification must establish. Successful commands/reads always use
the production public transport; only explicit fault controls hold the returned
acknowledgement, fail a selected read, or delay a production recovery read.

## Invariants

Exact command/proposal IDs survive explicit replay. Association mutations use
public commands. Impact receipts use the public read projection. Synthetic replies
carry a visible label and establish no real-model quality claim. Product files,
saved screenplay, placement and unrelated drafts remain under their existing owners.

## Revisit Triggers

A changed frozen source, native control label, command contract or qualifier delta
requires fresh admission and qualification evidence.

## Dependencies

Existing command/projection APIs, the Svelte runtime, the qualifier Vite config
and the established hosted Linux native/no-download setup. A bounded restart
checks saved proposal/binding reconstruction after the draft-preservation action
sequence; it does not qualify unsaved draft lifetime or project-switch recovery.

## Related ADRs

[ADR index](../../../docs/adr/README.md) records the repository's architectural
boundaries; the saved-edit reconciliation plan defines this bounded acceptance flow.

## Usage Examples

Build with `npx vite build --config ../scripts/manual-facts-vite.config.mts` from
`ui`. In the native fixture, use ordinary Analyze and review controls; use the
labelled QA buttons for exact replay, association ABA, canonical impact reads and
the explicitly synthetic held-acknowledgement/failed-read recovery sequence.


The separate save/refresh native successor admits product `1aab490` and only
the same nine QA files. Before ordinary acceptance the left inspector receives an
exact Unicode/whitespace selected-field draft plus an unselected motivation draft;
the right inspector remains clean. Acceptance must visibly refresh the right Bible
to canonical blue, preserve both left drafts and original red base, show the local
conflict and disabled Save/explicit discard, and retain all screenplay/placement.
Native text/character geometry receipts identify left versus right inspectors.
Non-whitespace glyph bounds must fit both each textarea and its Bible pane.
Ordinary Ctrl+Home navigation exposes the start after trailing blank lines without
changing text. Exact accessibility values retain every whitespace character.
Synthetic provider guards reject either unsaved Bible draft in analysis input.
No production files or canonical product state are replaced. Frozen `6e3bad3`
and its historical qualification/evidence branches remain unchanged.

After that established sequence, the clean right inspector submits exactly
`  Pending blue draft — 雨.\n\n  ` with ordinary Save. A labelled seam holds the
actual successful acknowledgement while another explicit public command commits
`Green saved fact — 雨.`. The ordinary detail read must show this newer fact;
releasing the older acknowledgement must retain exact text/base, conflict and
disabled Save. A separate unconflicted motivation draft survives a labelled detail
failure, ordinary pending Retry saved facts and verified recovery. Save must stay
disabled through failure and pending retry and become available only after the
owned recovery read; that draft is never submitted. All screenplay/placement and
provider call counts remain unchanged through this bounded fault sequence.
