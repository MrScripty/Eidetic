## Problem

Exact request/decision replay and consumed-association edit/restore need explicit
native fixture controls without changing production files or bypassing commands.

## Constraints

The exact ten-file qualifier delta is enumerated and admitted against the frozen source.
No model downloads, real inference, direct database writes, DOM/IPC injection or
automatic product actions are permitted. Detail failures and acknowledgement/read
delays are explicitly synthetic qualifier transport seams, not natural outages.

## Decision

A separate Vite config inserts the visibly labelled fixture controls into the
native test host. Wrappers forward analysis and decisions unchanged through the
existing public command API. Ordinary Save, select, Analyze, Reject and Accept
remain production controls driven with native X11 input and AT-SPI geometry.

## Alternatives Rejected

Direct SQLite writes and DOM scripting would bypass the ownership and native
behavior this qualification must establish. Successful commands/reads always use
the production public transport; only explicit fault controls hold the returned
acknowledgement, fail a selected read, or delay a production recovery read.

## Invariants

Exact command/proposal IDs survive explicit replay. Association mutations use
public commands. Impact receipts use the public read projection. Synthetic replies
carry a visible label and establish no real-model quality claim. Product files,
saved screenplay, placement and unrelated drafts remain under their existing owners.

## Revisit Triggers

A changed frozen source, native control label, command contract or qualifier delta
requires fresh admission and qualification evidence.

## Dependencies

Existing command/projection APIs, the Svelte runtime, the qualifier Vite config
and the established hosted Linux native/no-download setup. A bounded restart
checks saved proposal/binding reconstruction after the draft-preservation action
sequence; it does not qualify unsaved draft lifetime or project-switch recovery.

## Related ADRs

[ADR index](../../../docs/adr/README.md) records the repository's architectural
boundaries; the saved-edit reconciliation plan defines this bounded acceptance flow.

## Known-empty preview repair successor

The separate `test/known-empty-arc-preview-native` route first reruns the original
arc Description scenario with every original assertion retained. It then starts
three fresh native processes with isolated application-state and artifact folders:

- `known-empty-name`: ordinary ArcDetail Name edit while Description remains
  owned and empty; Preview shows honest empty-field evidence, explicit acceptance
  changes only B, and a later Description fill retains its precise dependency.
- `known-empty-second-tag`: one actual generated consumer has two empty tagged
  arcs. Ordinary Description editing and Preview/Accept preserve the second arc's
  omission separately. A later fill proves its dependency was not lost.
- `known-empty-deletion`: ordinary Name edit yields a pending preview; ordinary
  ArcDetail Delete makes old acceptance refuse without canonical writes. Reject
  and fresh Preview bind the owned deletion with no current arc prose. Explicit
  acceptance changes only B.

The two-tag project is an explicitly synthetic fixture. The existing public core
`Timeline::tag_node` model method seeds a fresh AppState/document manager. The
public `project_service::save_project` serializer persists it, then the fixture
loads it through `project_service::load_project` before
owned field commands and actual consumer generations. This does not represent a
user tagging UI or a JSON importer. The driver never writes directly to SQLite.
All later authoring interactions use ordinary native controls and production
commands. Read-only receipts verify both actual tag rows, owned empty clocks,
generated omission receipts and graph dependencies before the scenario starts.

The new native runs preserve exact manual B text, unrelated A/F blocks and spans,
locks, unselected segments, placement, Bible values and the unsaved F draft until
the specified explicit acceptance. The provider accepts only exact bounded prompt
shapes and returns five labelled synthetic calls for the name/two-tag cases or six
